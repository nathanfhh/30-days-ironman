# ADR 0020：前端改寫成 Vue 3，並用 golden master 逼出 1:1

- 狀態：已接受；已實作（legacy 於 2026-08-26 退場）

## 背景

管理畫面原本是「Jinja 模板 + 一支手寫的 `app.js`」：模板 1,909 行、`app.js` 2,090 行、
`app.css` 2,582 行，沒有建置鏈。它能動，而且動得不錯 —— 但有三個結構性的問題：

1. **19 處 `innerHTML`。** 每一列 session、每一顆 chip、每一個對話框都是用樣板字串拼出
   HTML 再塞進 DOM。逸出靠一支 `esc()`，而「哪些值需要逸出」是靠一份人維護的清單
   （`tests/test_web.py` 的 `TAINTED`）在守。漏列一個欄位就是一個無聲的洞。
2. **沒有元件邊界。** 「篩選列」不是一個東西，是散在模板、`app.js`、`app.css` 三個檔案裡
   的一組約定。改一處要記得改另外兩處，而沒有任何機制提醒你。
3. **測試只能從外面戳。** 沒有單元測試層，任何一條邏輯都要開瀏覽器才驗得到。

改寫的風險不在技術，在**回歸**：這個介面有很多「看起來是細節、其實是踩過坑才長成這樣」
的行為（chip 被切到才掛 tooltip、抽屜停定之後才送 PTY 尺寸、狀態確認超過兩分鐘要標紅），
它們散在那 4,600 行裡，沒有人記得完整清單。逐個重寫再靠人看，第三十個元件的時候一定
會漏。

## 決策

### 一、舊實作就是規格，用 golden master 逼出 1:1

改寫之前先把**現行畫面**錄成規格（`tests/golden/`），再拿新實作去對它。這是特徵測試
（characterization test）的做法：不預先寫下「應該長什麼樣」，而是把「現在長什麼樣」
記下來，任何偏離都要有人明確決定。

十八個場景，每一場錄**四份**，各守不同的東西：

| 快照 | 守什麼 | 為什麼單獨一份 |
|---|---|---|
| `aria.<vp>.txt` | 結構與可及名稱（role、accessible name） | 按鈕變成 div、標籤掉了、順序換了都會現形 |
| `dom.<vp>.txt` | 合約屬性（`data-testid` / `data-act` / `data-tone` / `data-kind` / `hidden` / `inert` / `aria-controls`…） | **aria 一個字都不記它們**，而它們是 e2e 的抓手、事件的分派鍵、狀態的真相來源 |
| `network.txt` | API 呼叫（含 query）、靜態資源、場景就緒時的網址 | 少帶一個篩選參數、offset 算錯，畫面看起來仍是一張表，資料卻是另一批 |
| `screen.<vp>.png` | 看起來還是不是同一個東西 | 前三份都是文字，抓不到版面與顏色 |

兩個視口（1280x800、390x844）各錄一份 aria 與 dom，media query 之後的結構也守得住。

### 二、不穩定源一律在**錄製端**釘死，不靠放寬閾值

放寬閾值是把問題藏起來：閾值放到 5% 之後，真的壞掉 4% 的那次也會是綠的。釘死的清單在
`golden_scenes.pin_all()` 與 `_settle()`，每一項都寫著它是什麼、為什麼會飄：登入頁的隨機
插畫、頁尾的 `build_info()`（會問 git sha 與 `ttyd --version`）、瀏覽器時鐘、登入後那則
「歡迎回來」toast、toast 的進度條（它同時是倒數計時器）、`users.created_at`、
`>= 5 秒的 setInterval`、字型的按需載入、Vite 產物檔名裡的內容雜湊。

### 三、截圖的三道閘，各接一種形狀

單一個「像素差比例」抓不到東西 —— 實測把抽屜面板的底色**整個換掉**，全頁只差 0.04%
（那塊底色幾乎被 iframe 與標題列蓋滿）。所以三道都要過：

| 閘 | 接的形狀 | 乾淨輪 | 7px 狀態燈換色 | chip 1px 邊框挪 20 階 |
|---|---|---|---|---|
| 比例 <= 1% | 大面積 | 0.00% | 過 | 過 |
| 不得有實心 5x5 強差異塊 | 局部一整塊 | 無 | **紅** | 過 |
| 強差異像素 <= 400 | 細而廣 | 0 個 | — | **紅（2160）** |

實心塊用**侵蝕**（`MinFilter(5)`）判而不是連通元件標記：連通元件的外接矩形會被細線騙
（整行文字位移一像素會產生 500x8 的細長元件，外接矩形遠大於 5x5，但它並不是「一塊」）。

## 後果

### 得到的

- **改寫真的是 1:1。** Vue 版全部補完之後，跨版比對是 109 條全 PASS，**十九張截圖全部
  逐像素通過**（不是落在容忍額度內，是 0.00%）。
- **抓到的具體回歸**（都是人眼審查不會發現的）：picker 選完之後收起來的選單 `aria-selected`
  停在舊值；對話框開著時觸發它的那顆列按鈕沒有 disabled；頁尾 `<time>` 與相對時間之間
  少了一個空白（整行窄 4px）；看歷史時建立表單舊版是 `hidden`、新版寫成 `v-if`。
- **`innerHTML` 歸零。** 逸出從「維護一份 TAINTED 清單」變成「框架保證，除非有人寫
  `v-html`」，而後者由 `test_web.py` 的靜態守衛擋著。
- 淨減 4,800 行（拆 legacy 那一刀）。

### 付出的

- **golden 是 6 MB 的二進位資產**（19 張全頁 PNG 佔 5.6 MB）。這是刻意的：截圖是唯一
  抓得到版面與顏色的那一份。
- **截圖只能在錄它的那台機器上比。** golden 錄在 macOS（PingFang TC），ubuntu runner 算繪
  出來的字是另一組像素。`tests/golden/META` 記下平台與 chromium 版本，`golden_check` 只在
  完全相同時才比截圖，否則**只跳過截圖**、aria／DOM／網路照比並明說跳了什麼。
  **所以 CI 全綠不等於四關全過** —— 動到版面之後要在本機跑一次
  `./tests/run-all.sh --e2e`，視覺那一關只有那裡驗得到。
- **重錄等於改規格。** 看到 `golden_check` 紅了就順手重錄，等於把「我改壞了」寫成「這就是
  新的對的樣子」，那條防線當場消失。重錄的 diff 要進 code review，與改一份 API 契約同一個
  份量。
- **自 `d79c87b` 起 golden 是 Vue 版自身的特徵快照**，守的是「不要回歸」，不再是「與舊版
  等價」。遷移期它拿 legacy 錄的那一份當規格，那個階段已經結束；現在它只回答「跟上一次
  錄的時候比，有沒有東西變了」。
- **已登入者冷載入 `/login` 由 SPA 的守衛導回**（`frontend/src/router.ts` 的 `beforeEach`）。
  Flask 的 302（`web.login_page`）**只在 dev 與 e2e 路徑生效** —— 正式部署那條路由由 nginx
  直接吐 `index.html`，請求根本不會走到 Flask。
- **已收緊：版號與主機路徑登入後才給。** `/api/bootstrap`（公開）原本回四件事，其中
  `build`（模組版本與 commit）與 `persist_dir`（宿主機上的絕對路徑）是**主機的內部事實**，
  對未登入的人只有一個用途：把「該打哪一個已知漏洞」印在門口。2026-08-26 兩者搬進
  `/api/account/bootstrap`，公開那條只剩 `behind_proxy` 與 `login_art`。
  **畫面同一刀一起收**：登入頁的頁尾整段不畫（`AppFooter.vue` 的 `v-if`）。只收 API
  不收畫面、或反過來，都只是讓人以為收緊了。代價寫在下一節：`login-empty` 與
  `login-error` 兩場的 golden 因此重錄過一次。

### 已知不涵蓋的

- **互動與時序** golden 是盲的（它錄的是靜止的一幀）：那是八支 Playwright e2e 的範圍。
- **元件內部的分支**：那是 `frontend/src/__tests__/` 的 vitest 範圍（行覆蓋率門檻 70%）。
- **`dom.txt` 只記白名單內的屬性**，不記 class、不記完整 HTML。記整棵 DOM 的話，多包一層
  wrapper 就會整份紅，而那種 golden 一週內就會被停用；停用之後連原本守得住的也一起沒了。

## 遷移的做法（保留紀錄）

兩版並存期間靠 `CLAUDE_PTY_UI=legacy|vue` 一個變數管兩端（Flask 的三條頁面路由、nginx 掛
哪一份片段），預設一直是 legacy。四關全過之後才拆 legacy，`CLAUDE_PTY_UI`、
`server/templates/`、`server/static/js/app.js`、`deploy/nginx-ui/legacy/` 同一刀移除。

拆的時候測試**逐條判**而不是逐條刪：每一條先問「它守的是什麼」，再問「那件事現在還存在
嗎、由誰負責」。對象消失的刪、搬家的換來源、裂成兩半的各歸各位。完整的對照表在
`docs/frontend-vue3-journal.md`。
